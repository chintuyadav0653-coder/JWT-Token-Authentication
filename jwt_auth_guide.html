Introduction to JWT

JSON Web Token (JWT) is an open standard (RFC 7519) that defines a compact and self-contained way for securely transmitting information between parties as a JSON object. This information can be verified and trusted because it is digitally signed.

The Structure of a JWT

A JWT consists of three parts separated by dots (.):

Header eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
.
Payload eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIn0
.
Signature SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
  • Header: Contains the token type (JWT) and the signing algorithm being used (e.g., HMAC SHA256 or RSA).
  • Payload: Contains the claims (statements about an entity/user and additional data). Never put secret data here, it's merely Base64 encoded, not encrypted!
  • Signature: Created by taking the encoded header, encoded payload, a secret, and the algorithm specified in the header to verify the token wasn't altered in transit.

Authentication Strategies

Choosing the right authentication strategy is critical for application scalability and security. Here is a comparison of the most common approaches.

Traditional

Session / Cookie Based

Stateful authentication where the server stores session data and the client stores a Session ID in a cookie.

  • Easy to revoke sessions instantly.
  • Highly secure if cookies are HttpOnly.
  • Harder to scale horizontally (requires session stores like Redis).
Modern

Token Based (JWT)

Stateless authentication where the server issues a signed token containing user claims, stored by the client.

  • Highly scalable (stateless server).
  • Excellent for mobile apps and microservices.
  • Hard to invalidate before expiration.

What about OAuth 2.0?

OAuth 2.0 is a delegated authorization framework (e.g., "Log in with Google"). It often uses JWTs under the hood for its Access and ID tokens (via OpenID Connect). It allows third-party applications to grant limited access to an HTTP service.

User Management Best Practices

Handling user data safely is the foundation of any auth system. Never store plain-text passwords. Always use a strong, slow hashing algorithm.

Password Hashing (Registration)

When a user registers, use bcrypt or argon2 to hash the password before saving it to the database. Bcrypt automatically handles "salting" to defend against rainbow table attacks.

const bcrypt = require('bcryptjs');

// During User Registration
async function registerUser(email, plainTextPassword) {
    const saltRounds = 10; // Determines computation time
    const hashedPassword = await bcrypt.hash(plainTextPassword, saltRounds);
    
    // Save 'email' and 'hashedPassword' to Database
    return db.users.insert({ email, password: hashedPassword });
}

Verifying Credentials (Login)

During login, retrieve the hashed password from the DB and compare it against the provided plain-text password using bcrypt's compare function.

// During User Login
async function loginUser(email, plainTextPassword) {
    const user = await db.users.findOne({ email });
    if (!user) throw new Error('User not found');

    // Securely compare hashes
    const isMatch = await bcrypt.compare(plainTextPassword, user.password);
    if (!isMatch) throw new Error('Invalid credentials');

}

Middleware Functions

In frameworks like Express, middleware functions execute during the lifecycle of a request to the server. An Authentication Middleware intercepts the request, checks for a valid JWT, and either allows access to the protected route or rejects it.

Standard Practice: The client sends the JWT in the Authorization HTTP header using the Bearer schema.
Authorization: Bearer <token>

The Anatomy of Auth Middleware

const jwt = require('jsonwebtoken');

const authenticateToken = (req, res, next) => {
    // 1. Extract token from header
    const authHeader = req.headers['authorization'];
    const token = authHeader && authHeader.split(' ')[1]; // "Bearer TOKEN" -> "TOKEN"

    // 2. No token? Unauthorized.
    if (!token) {
        return res.status(401).json({ message: 'Access denied. No token provided.' });
    }

    // 3. Verify token
    try {
        const decoded = jwt.verify(token, process.env.JWT_SECRET);
        
        // 4. Attach user payload to request object
        req.user = decoded; 
        
        // 5. Pass control to the next handler
        next();
    } catch (err) {
        // Token is invalid or expired
        return res.status(403).json({ message: 'Invalid or expired token.' });
    }
};

module.exports = authenticateToken;

Full Implementation (Node.js/Express)

Below is a complete, simplified Express application demonstrating Registration, Login, and a Protected Route tying all the concepts together.

server.js
require('dotenv').config();
const express = require('express');
const bcrypt = require('bcryptjs');
const jwt = require('jsonwebtoken');

const app = express();
app.use(express.json()); // Parse JSON bodies

// Mock Database
const usersDB = []; 
const JWT_SECRET = process.env.JWT_SECRET || 'super_secret_dev_key';

// --- MIDDLEWARE ---
const requireAuth = (req, res, next) => {
    const token = req.header('Authorization')?.split(' ')[1];
    if (!token) return res.status(401).json({ error: 'Unauthorized' });

    try {
        const payload = jwt.verify(token, JWT_SECRET);
        req.user = payload;
        next();
    } catch (err) {
        res.status(403).json({ error: 'Invalid Token' });
    }
};

// --- ROUTES ---

// 1. REGISTER
app.post('/api/register', async (req, res) => {
    try {
        const { username, password } = req.body;
        
        // Check if user exists
        if (usersDB.find(u => u.username === username)) {
            return res.status(400).json({ error: 'User exists' });
        }

        // Hash password
        const hashedPassword = await bcrypt.hash(password, 10);
        
        // Store user
        const newUser = { id: Date.now(), username, password: hashedPassword };
        usersDB.push(newUser);

        res.status(201).json({ message: 'User created successfully' });
    } catch (error) {
        res.status(500).json({ error: 'Server error' });
    }
});

// 2. LOGIN
app.post('/api/login', async (req, res) => {
    try {
        const { username, password } = req.body;
        
        // Find user
        const user = usersDB.find(u => u.username === username);
        if (!user) return res.status(400).json({ error: 'Invalid credentials' });

        // Compare password
        const validPassword = await bcrypt.compare(password, user.password);
        if (!validPassword) return res.status(400).json({ error: 'Invalid credentials' });

        // Generate JWT
        const token = jwt.sign(
            { id: user.id, username: user.username }, 
            JWT_SECRET, 
            { expiresIn: '1h' } // Token expires in 1 hour
        );

        res.json({ message: 'Logged in', token });
    } catch (error) {
        res.status(500).json({ error: 'Server error' });
    }
});

// 3. PROTECTED ROUTE
app.get('/api/dashboard', requireAuth, (req, res) => {
    // req.user contains the decoded JWT payload
    res.json({ 
        message: `Welcome to your dashboard, ${req.user.username}!`,
        secretData: "Here is your sensitive information."
    });
});

// Start Server
const PORT = 3000;
app.listen(PORT, () => console.log(`Server running on port ${PORT}`));
